# dsh-tally-ui 界面重设计

日期：2026-10-12
状态：已与用户逐节确认，待审阅
上位文档：[`2026-10-10-dsh-tally-design.md`](2026-10-10-dsh-tally-design.md)（§5.6 界面部分由本文档取代）

## 1. 背景与目标

用户在桌面客户端装上插件后反馈，`dsh-tally-ui` 看起来不像 dsh 自带的界面：

- 设置页是一长串表单往下堆，没有像 dsh 那样分组成卡片；
- 输入框只靠占位文字说明用途，填进内容后就看不出这一格是什么；
- 灰色按钮横跨整行，看起来像不能点；
- "路由 id""目标厂商"这类开发者配置，和预算、开关等日常设置混在一起；
- 被跳过的旧会话每个占一大段，刷满了"问题"一栏。

**目标**：在外观和信息结构两方面贴合 dsh 原生界面。用户选的是方案"外观 + 信息结构"，不是只换样式，也不是重新设计入口。

**实现方式**：原地重排（方案 A）。store、Remote 调用、记账逻辑都不动，只重写界面层的布局、交互和样式。

**判断成功的标准**：

1. 设置页、费用条、看板与 dsh 自带页面放在一起，看不出是第三方插件；
2. 日常设置（预算、界面开关）和高级设置（价格目录、价格覆盖、重建账本）分开；
3. 无论跳过多少个旧会话，"问题"一栏都只占一行。

## 2. 信息优先级

按使用频率排序，决定每项信息放在哪里：

| 优先级 | 信息 | 放在哪里 |
|---|---|---|
| 1 | 今日 / 本月费用 | 输入框下方费用条，常驻 |
| 2 | 预算进度与超限提醒 | 费用条（设了预算才显示）+ Toast 提醒 |
| 3 | 哪个会话 / 模型 / 工作区花钱多 | 右侧栏看板的排行 |
| 4 | 缓存命中率、峰谷节省 | 看板底部，默认收起 |
| 5 | 导出、对账 | 看板"⋯"菜单；对账只有命令行 |

## 3. dsh 原生规范（必须遵守）

来源：deepseek-harness 仓库的 `docs/web-styling.zh.md`、`docs/ui-radius.zh.md` 和 `packages/client/ui-primitives/README.zh.md` 中的组件目录。

- **设置卡片**：圆角 `var(--dsw-radius-xl)`（R20），描边 `0.5px solid var(--dsw-alias-settings-card-stroke)`，底色 `var(--dsw-alias-settings-card-fill)`。卡片内的行之间用 0.5px 中性发丝线分隔。
- **组件**：凡是组件库里已有的控件，一律用公共组件，不另写：`Button`、`Input`、`Switch`、`SegmentedControl`、`Modal`、`Menu`、`MenuItemButton`、`DisclosureRow`、`Tooltip`、`HoverCard`、`StateDot`、`Toast`、`Tag`。
- **颜色**：只用 `--dsw-alias-*` 语义变量，不写颜色字面量，不写主题选择器。
- **字号**：字号必须和行高成对出现；已有排版角色能对上的，用主题的排版变量。
- **焦点与动效**：保留清晰可见的键盘焦点；尊重"减少动态效果"偏好。
- **样式文件**：dsh 要求组件样式用 CSS Modules 放在组件旁边。要先确认 tsdown 打出的浏览器端产物能处理 CSS Modules，并通过 `scripts/check-client-bundle.mjs` 的检查。如果处理不了，保留现在带 `dsh-tally-` 前缀的全局类名，并在执行记录里写一条 Ruling 说明原因。

## 4. 设置页

从上到下依次是：卡片"预算"、卡片"界面"、卡片"问题"（有问题时才显示）、可展开的"高级"分组。

### 4.1 卡片：预算

- **每条预算占一行**：
  - 左侧主文字是"周期 · 范围"，例如"每日 · 全部工作区"或"每月 · ~/proj"；
  - 主文字下面一行小字写已用和上限，例如"已用 ¥3.20 / ¥10.00"；
  - 右侧显示百分比，再往右是"⋯"菜单（用 `Menu`），菜单里有"编辑"和"删除"；
  - 百分比的颜色：低于 80% 用中性色；80% 到 100% 用警告色；100% 及以上用错误色，文字改成"已超 ¥x"。
- **已用金额怎么算**：按这条预算的周期（今天或本月）和范围（某个工作区或全部），调用现有的用量查询算出。
- **添加和编辑都在弹窗里完成**（用 `Modal`）。弹窗里每一项都有可见的标签：
  - 周期：每日 / 每月，用 `SegmentedControl`；
  - 范围：下拉选择"全部工作区"或某个工作区。工作区列表来自账本里出现过的工作区（用现有的按工作区分组查询），不再让用户手填路径；
  - 金额：输入框，右侧是币种切换 CNY / USD；
  - 底部是"取消"和"保存"两个按钮；
  - 输入校验：金额必须是正数，最多两位小数；周期加范围相同的预算已经存在时，提示"已有相同的预算，请直接编辑"；
  - 保存失败时，在弹窗内显示服务端返回的错误文字，弹窗不关闭。
- **没有预算时**：卡片里显示一句"还没有设置预算。设置后，快超支时会提醒你。"，下面是"添加预算"按钮。

### 4.2 卡片：界面

5 个开关，每个一行：左边是名称，名称下面一行小字说明这个开关管什么，右边是 `Switch`。开关的行为不变，仍然即时生效。

| 开关 | 说明文字 |
|---|---|
| 输入框下方的费用条 | 显示今日、本月费用和预算进度 |
| 每轮对话的费用 | 在每轮回复末尾显示本轮费用 |
| 会话标题栏的累计费用 | 在会话标题旁显示本会话累计 |
| 右侧栏的用量页 | 在右侧栏显示用量看板 |
| 预算提醒 | 预算用到 80% 和 100% 时弹出提醒 |

### 4.3 卡片：问题

只在有问题时才显示这张卡片。

- **会话日志读取失败**：所有这类错误合并成一行"N 个会话的日志无法读取，已跳过"。点击后用 `DisclosureRow` 展开，列出每个会话的 id 和原始错误信息。文案不去推断具体原因，因为错误信息的格式由 dsh 决定。
- **账本、预算文件、价格覆盖的错误**：每类一行，用警告色。
- **账本可能损坏时**：保留现在的提示"可以在高级里重建账本"。

### 4.4 高级（默认收起）

用 `DisclosureRow` 做成可展开的分组，标题是"高级"。

- **价格目录**：
  - 每个模型一行，左边是模型名，右边依次是"生效于 2026-10-10"和"来源"链接；
  - 价格版本标识（例如 `deepseek-flash@2026-10-10`）不直接显示，只放进悬停提示；
  - 目录版本和"估算值，以账单为准"作为整张卡片的说明文字。
- **价格覆盖**：
  - 和预算一样，做成"列表 + 添加弹窗"。列表每行写这条覆盖的摘要，右边是"⋯"菜单，菜单里有"删除"；
  - 弹窗顶部用一句话说明用途："当某个路由用的是 DeepSeek 模型、但 tally 认不出来时，把它映射到已知模型，或者手动填写单价。"；
  - 路由用下拉选择，选项来自状态视图新增的 `routes` 字段（见 §7）；
  - 目标厂商和模型也用下拉，选项来自价格目录；
  - 自定义价格的单价输入沿用现在的校验规则；
  - 配置文件不可写时，整张卡片变为只读，并显示原因（行为和现在一样）。
- **重建账本**：一行，左边是说明"从会话日志重新生成账本，账本损坏或数据异常时使用"，右边是按钮。点击后先弹确认框；重建过程中显示进度；行为和现在一样。

## 5. 对话中的元素

### 5.1 输入框下方费用条

单行，样例：

```
今日 ¥1.23 · 本月 ¥20.10 · 预算 32% ▮▮▯▯▯ · 谷时 还剩 2:14:05
```

- **显示的项**：今日、本月、预算进度、峰谷时段，按这个顺序排列。
  - 去掉"本会话"，因为会话标题栏已经显示了；
  - 去掉常驻的余额，余额只出现在悬停卡片里。
- **预算进度**：只在设了预算时显示。
  - 有多条预算时，显示**用量比例最高**的那条；比例相同时，优先显示每日预算；
  - 颜色规则和 §4.1 相同；
  - 达到或超过 100% 时，文字改为"已超预算 ¥x"。
- **峰谷时段**：沿用现在的倒计时逻辑。前面加一个 `StateDot`：高峰用 `warning`，低谷用 `done`。
- **悬停或键盘聚焦时**：弹出 `HoverCard`，从上到下列出：
  - 本会话费用；
  - 今日费用；
  - 本月费用；
  - 每条预算的进度；
  - 余额（只在装了余额插件、有余额路由时显示）；
  - 当前时段的单价；
  - 最底部是"打开用量看板"链接。
- **点击费用条**：打开右侧栏的用量看板。
- **宽度不够时**：按"峰谷 → 本月 → 预算"的顺序依次省略，最后只留"今日 ¥x"，任何时候都不换行。
- **价格缺失**：查不到价格时显示"未定价"，绝不显示 ¥0，这条规则保持不变。

### 5.2 每轮费用

- 回复末尾显示一个 tertiary 色的小字金额。
- 悬停时用 `HoverCard` 显示明细：输入、缓存命中、输出、命中率、请求次数（含重试）、价格版本、价格来源。
- 和现在的区别只在明细卡的样式，以及行距改为 dsh 的规范值。

### 5.3 会话标题栏累计

- 显示为 tertiary 色的小字"本会话 ¥0.85"。
- 悬停时显示这个会话按模型拆分的费用和请求次数。
- 点击时打开看板，切到"排行 → 会话"，并高亮当前会话。

### 5.4 预算提醒

- 继续用 `Toast`。
- 文案改为"今日预算已用 82%（¥8.20 / ¥10.00）"，或"本月预算已超出（¥102.00 / ¥100.00）"。
- 后面带一个"查看"按钮，点击打开看板。

## 6. 右侧栏用量看板

整体是一列卡片，从上往下排。

- **顶部栏**：
  - 左边是标题"用量"；
  - 右边是时间范围 `SegmentedControl`，选项为 7 天 / 30 天 / 本月；
  - 再往右是"⋯"菜单（`Menu`），菜单里有"导出 CSV"，导出行为不变。
- **卡片 1：概览**：
  - 今日和本月两个大数字并排；
  - 下面一行小字是所选范围的合计和请求次数；
  - 每条预算一行进度条，颜色规则和 §4.1 相同；
  - 有未定价的请求时，加一行灰色小字"N 次请求未定价"。悬停说明原因，并附一个链接，点击跳到设置里的价格覆盖。
- **卡片 2：每日费用**：
  - 柱状图，每根柱子按高峰和低谷分两段叠放，图例放在图下方；
  - 悬停某根柱子时，用 `Tooltip` 显示当天的金额和峰谷拆分。
- **卡片 3：排行**：
  - 用 `SegmentedControl` 在会话、模型、工作区三类之间切换，一次只显示一张表；
  - 默认显示前 10 名，底部有"显示全部"；
  - 每行显示名称、金额和一条占比横条；
  - 已删除的会话加一个 `Tag`，文字是"已删除"；
  - 从会话标题栏点进来时，自动切到"会话"并高亮当前会话。
- **卡片 4：缓存与峰谷**：
  - 用 `DisclosureRow`，默认收起；
  - 展开后是缓存命中率的趋势线，以及一句"本期因低谷时段节省约 ¥x"。
- **特殊状态**：
  - 加载中：各卡片显示灰色占位块，不出现"加载中…"文字；
  - 没有数据：显示一句话"还没有用量记录，开始一次对话后这里会显示费用"；
  - 加载失败：在卡片内显示错误提示和"重试"按钮。

## 7. 数据与接口

- **唯一的接口变更**：`TallyStatusView` 新增字段 `routes: string[]`，内容是 dsh 已配置的 LLM 路由加上账本里出现过的路由，去重后按字典序排序。这是只增不减的修改，符合"接口只做加法"的承诺。
- **用量查询**：本月费用、各条预算的已用金额、工作区列表都用现有的用量查询完成，不新增方法。
- **不改动**：store 的订阅模型、`watch` 帧、记账、余额插件、对账命令都保持不变。

## 8. 测试

- **单元测试**（纯逻辑，测试先写）：
  - 多条预算时挑出要显示的那条：比例最高；比例相同时优先每日预算；
  - 费用条宽度不足时的省略顺序；
  - 会话读取失败的合并和计数；
  - 预算弹窗的校验：正数、两位小数、重复的周期加范围；
  - 价格覆盖弹窗的校验；
  - `routes` 字段的生成：去重并排序。
- **端到端测试**：
  - 现有 7 项改用新结构里的 `data-tally` 定位；
  - 新增"添加预算弹窗"；
  - 新增"高级分组展开后能看到价格目录"；
  - 新增"多个跳过会话合并为一行"。这一项要构造无法读取的会话日志；如果用 dsh 的 fixture 做不出来，就降级成单元测试，并写一条 Ruling。
- **截图**：设置页、看板、费用条各截一张浅色主题和一张深色主题的图，保存到 `packages/tally-ui/tests/e2e/screenshots/`，供用户查看效果。
- **兼容性**：dsh latest 和 alpha 两个版本的 CI 继续运行。

## 9. 范围之外

- 余额插件、对账命令、记账和计价逻辑；
- dsh 自带的任何页面，包括"账号与余额"；
- 新的统计维度或图表类型；
- 在 dsh 设置侧栏里新增多个设置入口（方案 C，已否决）。
